## 보도자료 (Press Release)

### token-forge 1.0 공개 — 명령 한 줄로 내 AWS 계정에 뜨는 프라이빗 바이브 코딩 LLM

**오픈 웨이트 코딩 모델을 스팟 인스턴스로 월 $200 이하에, 코드 한 줄 밖으로 내보내지 않고 Claude Code에 연결한다**

서울 — 2026년 4분기, roboco는 개발자가 자신의 AWS 계정 안에서 프라이빗 LLM 코딩
환경을 운영할 수 있게 하는 오픈소스 CLI, token-forge 1.0을 공개했다.

AI 코딩 도구는 이제 개발자의 일상이지만, 두 가지 벽이 있다. 회사 코드를 외부 API로
보낼 수 없는 개발자는 아예 쓸 수 없고, 쓸 수 있는 개발자도 구독 한도와 요금에 발이
묶인다. 오픈 웨이트 모델을 직접 서빙하면 되지만, 현실은 가혹하다 — GPU 온디맨드는
시간당 수만 원이고, 싼 스팟 인스턴스는 리전과 가용영역마다 확보 가능성이 시시각각
달라져서 "오늘은 어느 리전에 뜰까"를 사람이 알아맞혀야 했다.

token-forge는 이 확보 문제를 데이터로 푼다. roboco가 상시 수집·공개하는 스팟
배치점수 추이를 바탕으로 확보 확률이 높은 리전 후보를 고르고, **후보 리전들에
동시에 스팟을 요청해 먼저 잡히는 곳만 남기고 나머지는 즉시 취소**한다(병렬 레이스).
개발자는 리전을 몰라도 된다. `tf up` 한 번이면 평균 8분 뒤 OpenAI·Anthropic 호환
엔드포인트가 뜨고, `tf connect claude` 한 번이면 Claude Code가 그 엔드포인트로
동작한다. 프롬프트도, 응답도, 사용량 통계조차도 계정 밖으로 나가지 않는다.

비용은 구독 서비스와 같은 자릿수다. 30B급 코딩 모델 기준 하루 3~4시간 사용 시
월 $100~200 — 쓰지 않는 시간에는 자동으로 꺼지고, 가중치는 미리 S3에 적재해
GPU가 다운로드에 시간을 쓰지 않는다. 스팟이 회수되면 여러 타입·가용영역·리전에
걸친 자동 재확보가 수 분 내 세션을 복구한다.

"GPU 스팟 서빙의 진짜 장벽은 vLLM 설정이 아니라 '지금 어디서 잡히는가'였습니다.
우리는 250B 모델을 스팟으로 서빙하며 그 답을 데이터 파이프라인으로 만들었고,
그걸 명령 한 줄에 담았습니다." — 정도현, roboco

"회사 규정상 외부 LLM API를 못 쓰는데, 이제 제 계정 안에서 Claude Code를 씁니다.
아침에 `tf up` 걸어놓고 커피 타 오면 준비가 끝나 있어요. 지난달 GPU 요금은
14만 원이었습니다." — 베타 사용자, 금융권 백엔드 개발자

시작하려면 AWS 계정과 스팟 쿼터만 있으면 된다. `npm install -g token-forge` 후
`tf up qwen3-coder-30b`를 실행하라. 전체 코드는 GitHub(roboco-io/token-forge)에
공개돼 있어 계정 안에서 무엇이 실행되는지 직접 감사할 수 있다.

## FAQ

### 고객 FAQ

**Q1. 얼마가 드나?**
30B급 코딩 모델(권장 기본) 기준 g6e.12xlarge 스팟 ~$2.6/h. 일 3~4시간 × 20일이면
월 $100~200이다. 유휴 30분이면 자동 정지되므로 켜둔 채 잊어도 하루 종일 과금되지
않는다. 대형 모델(GLM-4.6급, 8×L40S 또는 8×H100)은 시간당 $11~22로 이 목표
범위를 벗어나는 명시적 선택사항이다. 부수 비용: 가중치 S3 보관(리전당 $1~8/월),
스탠바이 리전 ALB(리전당 ~$16/월, `single` 모드로 줄일 수 있음).

**Q2. 내 코드와 프롬프트는 어디로 가나?**
어디로도 가지 않는다. 추론은 당신 계정의 GPU에서 일어나고, 프롬프트·응답은 물론
사용량 통계도 밖으로 전송되지 않는다. 외부 통신은 세 가지뿐이다: Hugging Face
가중치 다운로드, AWS API 호출, 그리고 roboco 공개 배치점수 피드의 익명 조회(어느
리전이 유리한지 읽기만 한다). 이 마지막 것도 차단하고 싶으면 프라이버시 모드로
자가 수집기를 돌리면 된다. 전송 구간은 TLS로 보호된다.

**Q3. Claude Code에 어떻게 연결하나?**
`tf connect claude`가 `ANTHROPIC_BASE_URL`·인증 토큰·모델명을 자동 구성한다.
vLLM의 네이티브 Anthropic 호환 API(`/v1/messages`)를 쓰므로 변환 프록시가 없고,
도구 호출·스트리밍·서브에이전트 팬아웃까지 검증돼 있다. Cursor·Aider 등 OpenAI
호환 도구는 같은 엔드포인트의 `/v1/chat/completions`를 쓰면 된다.

**Q4. 스팟이 회수되면 코딩 세션은 어떻게 되나?**
진행 중이던 요청은 실패하고, 여러 인스턴스 타입·가용영역에 걸친 자동 재확보가
시작된다. 수용 기준은 "10분 내 같은 대화의 다음 요청이 정상 응답"이다. Claude Code
쪽 대화 기록은 클라이언트에 있으므로 잃지 않는다. 무중단이 필요하면 상시 대기
레플리카가 필요한데, 그건 v1 범위 밖이다 — 우리는 "수 분 대기를 감수하고 반값
이하"라는 트레이드오프를 명시적으로 판다.

**Q5. 어느 리전에 뜨는지 내가 신경 써야 하나?**
아니다. 배치점수 48시간 추이 → 내 위치 기준 레이턴시 → 가격 순으로 후보를 고르고,
상위 후보 리전들에 병렬로 확보를 시도해 먼저 잡힌 곳만 남긴다. 배치점수는 확률
신호라 단일 리전 베팅은 빗나간다 — 우리 실측에서 같은 리전이 같은 날 33초 만에
잡히기도, 30분간 마르기도 했다. 그래서 예측(후보 선정)과 헤지(병렬 레이스)를
분리했다.

**Q6. 어떤 모델을 쓸 수 있나?**
검증된 카탈로그에서 고른다(출시 시점: Qwen3-Coder-30B, GLM-4.6, Solar Open2 250B —
각각 실서빙으로 검증됨). 카탈로그에 없는 모델은 YAML 프로파일 하나를 추가하면
되지만, 양자화 MoE 모델의 병렬화 설정 같은 함정이 있어 검증된 항목 사용을 권한다.
모델은 한 번에 하나가 뜨고 프로파일 교체로 전환한다.

**Q7. 처음 쓸 때 얼마나 걸리나?**
스팟 쿼터가 있다는 전제에서, 첫 모델은 가중치 선시딩(저가 CPU 인스턴스가 S3에
적재, 30B급 ~8분/$0.03) 포함 약 20분. 이후 기동은 캐시에서 로드하므로 평균 8분이다.
쿼터가 없는 계정(신규 기본값 0)은 증설 신청이 선행돼야 하며 CLI가 리전별 현황과
신청 가이드를 안내한다.

**Q8. 왜 서버리스(요청당 과금)가 아닌가?**
바이브 코딩은 세션 동안 요청이 연속되고 128K 컨텍스트의 prefix cache가 성능을
좌우한다. 요청마다 콜드스타트하는 서버리스 모델과 근본적으로 맞지 않는다.
token-forge는 "세션 동안 켜져 있고, 세션이 끝나면 꺼지는" 모델이다.

### 내부 FAQ

**Q9. 스팟 할인이 줄어들면 사업 전제가 무너지지 않나?**
리스크는 실재한다. 다만 이 제품의 가치는 할인율 자체가 아니라 "확보 불확실성의
자동화"다. 할인율이 줄어도 온디맨드 대비 우위와 프라이버시 가치는 남고, 인터페이스는
클라우드 중립으로 설계해 확장 여지를 둔다. 관련 지표(리전별 스팟가)는 이미 상시
수집 중이라 변화를 가장 먼저 안다.

**Q10. 오픈 웨이트 모델이 상용 최상위 모델보다 코딩을 못하면?**
사실이고, 그래서 앵커 고객이 중요하다. 우리 앵커는 "최고 모델을 못 쓰는 사람"
(프라이버시 제약)과 "한도에 묶인 파워유저"다. 이들에게 대안은 상용 최상위가 아니라
'아무것도 없음' 또는 '한도 초과 후 대기'다. 오픈 웨이트 코딩 모델의 상향 속도는
우리가 통제할 수 없지만, 카탈로그 구조상 새 모델 편입은 YAML 하나다.

**Q11. SkyPilot 같은 오픈소스와 뭐가 다른가?**
SkyPilot은 범용 멀티클라우드 잡 오케스트레이터다 — 강력하지만 "바이브 코딩 LLM
엔드포인트"라는 완성된 경험이 아니라 도구 상자다. token-forge는 용도를 좁혀서
얻는 것을 판다: 검증된 모델 카탈로그, 상시 수집된 배치점수 추이(도구가 아니라
데이터), Claude Code 원커맨드 연결, 그리고 확보 레이스까지 포함한 `up` 하나의 UX.

**Q12. 무료 OSS인데 roboco는 뭘 얻나?**
오픈코어 전략의 무료 티어다. OSS와 공개 피드가 수요 신호(피드 사용량, "대신
운영해달라"는 문의)를 모으고, 신호가 임계를 넘으면 매니지드 컨트롤 플레인(팀·기업
대상)을 유료로 얹는다. 데이터 플레인이 공개라는 사실 자체가 그 단계에서 "고객
계정에서 도는 코드를 감사할 수 있다"는 영업 논리가 된다.

**Q13. 가장 큰 미검증 가설은 무엇인가?**
"개인 개발자가 8분 기동 대기와 세션당 수 센트~수 달러의 변동비를 구독의 정액
편리함과 바꿀 것인가"다. 기술 스택은 실배포로 검증됐지만(서빙·시딩·레이스 재료·
Anthropic API·prefix caching), 이 행동 가설은 출시 후 피드 사용량과 리텐션으로만
검증된다. 실패 신호가 오면 개인 앵커를 접고 플랫폼팀(팀 단위 상시 가동) 앵커로
전환한다 — 인프라는 동일하다.

**Q14. 왜 지금인가?**
세 곡선이 교차했다. ① 오픈 웨이트 코딩 모델이 실용 임계를 넘었고(도구 호출 포함),
② vLLM이 Anthropic 호환 API를 네이티브로 실었으며, ③ 코딩 에이전트 보급으로
"내 인프라의 LLM" 수요가 프라이버시 민감층 밖으로 확산되고 있다. 6개월 전에는
②가 없어 변환 레이어가 필요했고, 6개월 뒤에는 선점 기회가 줄어든다.
