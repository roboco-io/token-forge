# 부팅 비용 관측과 임계 경로 개선 (#45)

## 범위와 승인

이슈 #45, `feat/boot-cost-observability`, 시작점 `b35b018`(v1.1.0).
승인된 설계 안에서 구현한다. 실제 Ralph 반복 1은 구현/검증 후 종료하고, 다음 반복에서 실제 diff를 fresh 리뷰한다.
다른 에이전트는 사용하지 않는다. 커밋·push·배포·GPU 조작·이슈 수정·릴리스는 수행하지 않는다.
실행기의 실제 마지막 응답은 부모 어댑터가 official Ralph Stop hook에 전달한다. 기존 GPU 비용 가드의 읽기 조회를 유지한다.

## 최종 설계와 가정

- 기존 7개 placeholder, 모델·flags·secret·S3 `.complete` marker/HF 3회 재시도,
  Docker restart/로그 드라이버를 보존한다. `__BOOT_LOG_GROUP__`만 추가한다.
- 호스트의 Bash와 Python 3 표준 라이브러리로 동작한다. Python 감독 코드는 user-data에 inline으로 포함한다.
  helper 설치, 외부 계측 서비스, 새 의존성, 새 CDK context는 없다.
- 이미지 inspect/pull과 weights 준비를 서로 다른 프로세스 그룹에서 병렬 실행한다.
  `TKF_BOOT_MODE=serial`은 비교용 호스트 환경 옵션이다. 두 작업 성공 후 secret 조회와 docker run을 수행한다.
- supervisor가 양쪽 상태를 polling하여 어느 쪽 실패든 즉시 감지하고 TERM/KILL 후 직접 자식을 회수한다.
  SIGINT/SIGTERM도 같은 정리를 수행한다. 세션을 탈출한 자손이나 Docker daemon 내부 전송까지 중단한다고 보장하지 않는다.
- 전체 호스트 기동 상한 1,800초, health 상한 1,200초(전체 상한 이내). `TKF_BOOT_TIMEOUT` /
  `TKF_HEALTH_TIMEOUT`은 0 초과 1,800 이하만 허용한다. CLI 기본 30분 전체 대기·기존 비용 가드는 변경하지 않는다.
- v1 이벤트는 boot UUID, seq, wall epoch ms, monotonic elapsed/duration, 고정 phase/status/cache만 포함한다.
  subprocess stdout/stderr를 구조화 로그에 복사하지 않는다. 비밀/명령 인자/인증헤더/프롬프트/응답을 기록하지 않는다.
- 호스트 `/var/log/token-forge/events.jsonl`에 append하고 별도 스레드가 CloudWatch에 배치 전송한다.
  스택별 그룹은 7일 보존/Retain, `BootLogGroupName` 출력. 기존 IAM 로그 쓰기 범위를 넓히지 않는다.
  sequenceToken 없이 timestamp 순서로 전송하고 부분 거부를 실패로 처리한다. 무한 재시도하지 않는다.
  READY는 upload 완료 전에 기록한다. 즉시 종료·호스트 유실 시 best effort 유실 가능성이 있다.
- `tkf boot-report --file`은 JSONL 또는 CloudWatch export만 읽는다. 단일 boot에만 launch anchor를 적용한다.
  병렬 duration 합산 금지, 누락/충돌/시간 이상은 불완전 표시, 단가와 유효 launch anchor 없이는 비용 null.
  알려진 안전 필드만 출력하며 잘못된 입력 원문도 오류 메시지에 노출하지 않는다.
- host→local READY는 부분 관측이다. EC2 launch→READY의 고정 단가 근사는 청구서가 아니다.
  CLI 전체 대기·serving·idle tail·종료 전파·전체 세션 비용을 측정했다고 주장하지 않는다.
- README EN/KO/JA에 로그 수집·보고·동일 조건 A-B·첫/S3/로컬 이미지 기동 구분과 한계를 기록한다.
  과거 8분은 개선 후 실측으로 재사용하지 않는다. 외부 T4 96%와 시뮬레이션 지연을 성능 근거로 사용하지 않는다.

3. **확장 검증**: 양방향 실패 시 손자 종료, SIGINT/SIGTERM, local image 재사용, S3 hit/miss,

5. **보고서 검증**: 겹침·순서 뒤섞임·중복·누락·충돌·다중 boot·부분 실패·지원하지 않는 버전·

## 첫 반복 종료 당시 리뷰 상태

이번 반복은 구현과 위 검증까지 수행했다. **fresh diff 리뷰는 아직 남았다.**
다음 반복은 기존 파일과 `result.json`/실행 로그를 먼저 읽고 실패 정리·전송 범위·비밀 비노출·CLI 호환성을 다시 검토한다.
수정이 없으면 검증을 불필요하게 반복하지 않는다. 수정하면 해당 회귀와 마지막 전체 검증을 갱신한다.
부모 실행기가 실제 마지막 응답을 official Ralph Stop hook에 전달하므로 응답을 조작하거나 별도 Claude 명령을 실행하지 않는다.

첫 반복에서는 완료 promise를 출력하지 않는다. 실제 GPU A-B·배포·이슈 close·릴리스는 자동 수행하지 않는다.

## Ralph 반복 2: fresh 리뷰와 수정

기존 파일, 첫 반복 결과 JSON 및 실제 검증 로그, 전체 diff와 추가 파일을 다시 읽었다.
다른 에이전트·Claude 전용 명령·추가 승인 없이 승인 범위에서 아래를 수정했다.

- **producer↔parser 계약**: upload 상태가 core 순번에 섞였다. 이제 `stream: "telemetry"`와
  독립 seq를 가진 호스트 전용 기록이다. core 큐는 업로드를 생성하지 않는다. 보고서는 core 누락을
  계속 탐지하며 telemetry는 전송 실패 집계에 사용한다. READY 뒤 전송 시간은 부팅/비용에서 제외한다.
- **스트림 재시도**: 생성 응답 유실 뒤 ResourceAlreadyExistsException만 기존 스트림 재사용으로 처리한다.
  AccessDenied 등 다른 오류와 HTTP 200 부분 거부는 계측 유실 가능성으로 기록한다. stderr 원문은 출력하지 않는다.
- **안전한 진단**: 확인한 cache branch를 실패 이벤트에도 보존하고 정수 exit_code를 추가했다.
  docker run 실패와 unexpected subprocess 예외에서 stdout/stderr/JSON/CW capture의 비밀 비노출을 검증한다.
- **로컬 기록 실패**: 고정 진단 `TKF_LOCAL_LOG_WRITE_FAILED`를 내고 기동/메모리 큐/원격 전송을 계속한다.
  호스트 원본이 없을 수 있다는 관측 한계를 README 3개 언어와 architecture에 명시했다.
- **종료 경계**: daemon uploader를 버리지 않고 drain 기한 후 새 subprocess를 금지한 뒤 현재 그룹을
  종료하고 스레드를 회수한다. 호출 timeout은 4초이고 재시도는 최대 2회다.
  테스트에서 join 기한만 짧게 주입해 deadline 경로를 실행하고 실제 AWS stub 자식·손자의 소멸을 확인한다.
- **취소/고아 프로세스**: serial 및 image cache hit 경로에서도 SIGTERM 뒤 손자 소멸을 검사한다.
  준비 helper가 먼저 성공 종료하고 손자를 남긴 경우도 실제 프로세스로 검사한다.
  supervisor 자체 SIGKILL/OOM, 세션 탈출 자손, Docker daemon 내부 전송은 정리 보장 대상이 아니다.
- **시계**: 1ms 벽시계 역행을 정상 비용으로 받아들이던 사례를 재현했다. 역행 또는 단조 시계와
  2ms 반올림 허용치 초과 불일치가 있으면 불완전 처리하고 비용을 산출하지 않는다.
  서로 다른 boot의 시간 이상을 합치지 않으며 단일 anchor를 다중 boot에 적용하지 않는다.
