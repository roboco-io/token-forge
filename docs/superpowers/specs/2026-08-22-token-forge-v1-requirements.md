# token-forge v1 요건 정의 — 프라이빗 바이브 코딩 LLM

> 2026-08-22 심층 인터뷰(10문항 + 추가 요건 1건)로 확정. 설계 스펙의 상위 문서이며,
> 이후 구현 계획은 이 요건을 기준으로 검증한다.

## 제품 정체성

**"내 AWS 계정 안에서 도는 프라이빗 바이브 코딩 LLM."**
오픈 웨이트 모델을 스팟 인스턴스로 값싸게, 배치점수 인텔리전스로 안정적으로 서빙하고,
Claude Code 등 코딩 에이전트가 바로 붙는 API를 제공하는 OSS 셀프서브 CLI.

## 앵커 고객과 확장 경로

**v1 앵커: 개인/소규모 파워유저** — 자기 AWS 계정을 가진 개발자가 구독료 대신
자기 인프라의 LLM으로 바이브 코딩. 확장 순서: ① 기술 기업 플랫폼팀(멀티유저 관리)
→ ② 규제 산업 개발팀(격리 증빙·망분리). v1은 앵커만 완벽히 만족시킨다.

## 요건

| # | 영역 | 요건 |
|---|---|---|
| R1 | 고객 | 개인 파워유저 셀프서브 — 간편함이 1순위 품질 속성 |
| R2 | 프라이버시 | 프롬프트·응답·**메타데이터(사용량 통계 포함) 모두 계정 밖 불반출**. 외부 통신은 ① HF 가중치 다운로드 ② AWS API ③ 로보코 공개 배치점수 피드의 **익명 읽기 전용 GET**(프롬프트와 무관, 아래 R10 참조)이 전부. 텔레메트리 일절 없음. 피드 조회조차 차단하려면 **프라이버시 모드**(자가 수집기 `-c collector=1`) 선택 가능 |
| R3 | 세션 연속성 | 스팟 인터럽션 시 수 분 대기 허용. 웜 스탠바이 없음 — 다중 타입/AZ 후보 + ASG 자동 재확보로 복구. 수용 기준: **인터럽션 후 10분 내 동일 대화의 다음 요청이 정상 응답** (prefix cache 콜드는 허용 — vLLM은 서버측 세션 상태가 없음) |
| R4 | 모델 운용 | 테넌시당 단일 모델(GPU 1세트) + 프로파일 교체로 전환. 검증된 모델 카탈로그 제공 |
| R5 | 클라이언트 | Claude Code(대화형·SDK·서브에이전트)와 OpenAI 호환 도구 모두 1급 지원. Anthropic `/v1/messages`는 vLLM 네이티브 사용. **"1급" 수용 기준**: smoke-test 통과 + 도구 호출 왕복 1회 + 스트리밍 + 동시 요청 10개 팬아웃 정상 |
| R6 | 동시성 | 1인 + 에이전트 팬아웃 = 순간 ~10 동시 요청, 128K 컨텍스트, prefix caching 필수 |
| R7 | 비용 | 월 $100~200 목표. **기준 가정: 30B급 코딩 모델(예: Qwen3-Coder-30B) × g6e.12xlarge 스팟(~$2.6/h) × 일 3~4시간 × 20일**. 대형 모델(GLM-4.6급 이상, 48xlarge)은 이 목표 밖의 명시적 선택사항. 수단: 쓸 때만 기동, 유휴 자동 정지 기본, 가중치 선시딩 |
| R8 | 기동 UX | 명시적 명령 1회 → 진행률 표시. 수용 기준: **가중치 캐시 존재 + 스팟 즉시 배정 시 p50 ≤ 8분**(실측 8분24초). 첫 기동(캐시 없음)은 선시딩 포함 ~20분으로 별도 안내. 스팟 대기 시 진행 상황 표시 + 타임아웃(기본 30분) 후 대안 리전 제안 |
| R9 | 제공 형태 | OSS 셀프서브 CLI. 운영 주체는 사용자 본인, 로보코 서버 관여 0 — R2를 구조적으로 증명 |
| R10 | **지능형 배치** | `up <model>` 요청 시 **여러 리전·AZ 중 스팟 배치점수·가격·레이턴시·필요 용량을 종합해 최적 위치를 자동 선택**하여 스팟 클러스터 생성. 사용자는 리전을 몰라도 된다 |
| R11 | **전송 보안** | **TLS 필수** — 프롬프트가 평문으로 인터넷을 지나지 않는다(구현 방식은 설계 단계에서: CloudFront 앞단 등). API 키는 Secrets Manager 보관·회전 명령 제공. 네트워크 노출 축소 옵션(소스 IP 허용목록) 제공 |

## R10 지능형 배치 엔진 (v1의 두뇌)

**입력**:
- 배치점수 추이 — 공개 피드 `data.json` (48h 평균 우선, [docs/spot-feed.md](../../spot-feed.md)).
  익명 읽기 전용 GET이며 프롬프트·계정 정보와 무관(R2 허용 예외). 프라이버시 모드에서는
  자가 수집기 데이터로 대체
- 스팟 가격 — 피드 + 실시간 API
- 레이턴시 — **CLI가 후보 리전의 EC2 엔드포인트(`ec2.<region>.amazonaws.com`)에
  TCP 연결 시간 3회 측정 후 중앙값**, 결과는 로컬 캐시(24h)
- 필요 용량 — `models/<model>.yaml` 프로파일의 인스턴스 요구
- (파생) 계정 쿼터 — 리전별 스팟 vCPU 한도(Service Quotas API, 로컬 조회)
- (파생) 가중치 캐시 위치 — 캐시 없는 리전은 선시딩 시간·비용 가산

**실패 경로 (요건)**:
- 피드가 대상 타입·리전을 커버하지 않거나 피드 접근 불가 → GetSpotPlacementScores
  실시간 호출로 폴백(추이 없이 현재값만, 사용자에게 고지)
- 모든 후보 리전의 가용 쿼터가 필요 vCPU 미만(신규 계정 기본 0) → 리전별 쿼터 증설
  가이드([docs/ec2-quota-guide.md](../../ec2-quota-guide.md))를 안내하고 중단

**"클러스터"의 v1 범위**: 레플리카 1개(단일 노드, R4·R6과 일치)를 최적 위치에 배치하는
것을 뜻한다. 다중 레플리카·리전 간 라우팅은 확장 단계의 범위다.

**우선순위와 동치 기준**: **확보 안정성 → 레이턴시 → 가격** 순으로 비교하되, 연속값이므로
동치 임계값을 둔다 — 48h 평균 배치점수 차 **< 1**이면 동점으로 보고 레이턴시 비교,
RTT 차 **< 30ms**면 동점으로 보고 가격 비교. (임계값은 구현에서 조정 가능하나 기본값은 이것)
근거: 앵커 워크로드가 대화형 코딩이므로 "끊기지 않음"이 최우선, 가격은 이미 스팟으로
구조적 절감이 되어 있으므로 최후 순위. (2026-08-22 실측: 서울 g6e는 같은 날에도
33초 확보 ↔ 30분 고갈을 오감 — 시간대·리전 분산의 실증 근거)

## 파생 기능 요구 (현재 코드와의 갭)

1. **통합 CLI** — `up / down / status / model(카탈로그·교체) / connect` 서브커맨드,
   기동 진행률 표시. 현재 산재한 `cdk deploy` 컨텍스트와 scripts/*.sh를 대체
2. **Claude Code 원커맨드 연결** — 엔드포인트·API 키·모델명 env 자동 구성
   (`ANTHROPIC_BASE_URL`/`ANTHROPIC_AUTH_TOKEN`/`ANTHROPIC_MODEL`)
3. **배치 엔진** — R10. 피드 소비 + 쿼터 조회 + 추천/자동 선택
4. **멀티리전 스택 관리** — 선택된 리전에 스택 생성·시딩·기동을 CLI가 오케스트레이션.
   **잔존물 정책**: `down` = 정지(스택·가중치 캐시 유지, 재기동 빠름), `down --purge` =
   해당 리전 스택·캐시 완전 삭제. 가중치 캐시 보유 리전은 기본 최대 2개 — 초과 시 가장
   오래 안 쓴 리전 캐시 정리를 제안 (리전당 150~340GB S3 비용 방지)
5. **전송 보안(R11)** — TLS 종단, 키 회전 명령, 소스 IP 허용목록 옵션

이미 구현·실증된 것(재사용): CDK 스택(100% 스팟·다중 후보·유휴 정지), boot.sh(S3 캐시),
seed-weights.sh(선시딩), 모델 카탈로그 3종(Solar Open2·GLM-4.6·Qwen3-Coder-30B),
`/v1/messages`·prefix caching·Claude Code 도구 호출(전부 실배포 검증), 배치점수 공개 피드.

## 비범위 (v1에서 하지 않는 것)

- 멀티유저 관리·팀 쿼터·과금 분리 (플랫폼팀 단계)
- 웜 스탠바이 무중단 페일오버 (R3에서 배제)
- 멀티모델 동시 서빙 (R4에서 배제)
- 매니지드 운영·크로스계정 컨트롤 플레인 (수요 게이트 통과 후)
- 망분리 완전 오프라인 (규제팀 단계)

## 성공 기준 (가설 — 출시 후 검증)

- 개인 개발자가 일 3~4시간 코딩 세션을 이 API만으로 완주하고(30B급 기준), 월 GPU 비용이 $200을 넘지 않는다
- `up`부터 Claude Code 첫 응답까지 10분 이내(캐시 히트 기준), 설정 작업은 명령 2개(up + connect) 이내
- 스팟 인터럽션 후 10분 내 동일 대화의 다음 요청이 정상 응답한다 (R3 수용 기준과 동일)

## 용어

- **테넌시**: 한 사용자의 AWS 계정에 배포된 token-forge 스택 일체(리전 이동 시에도 논리적으로 하나)
- **선시딩**: GPU 기동 전에 저가 CPU 인스턴스로 HF 가중치를 S3에 미리 적재하는 것 (`scripts/seed-weights.sh`)
- **웜 스탠바이**: 장애 대비로 예비 GPU를 미리 켜두는 것 — v1에서는 하지 않음
- **배치점수(SPS)**: AWS `GetSpotPlacementScores`가 주는 1~10 스팟 확보 가능성 선행 지표
- **EP(expert parallelism)**: MoE 모델의 expert를 GPU에 통째로 분산하는 병렬화 — 블록/그룹
  양자화 모델에서 TP(tensor parallelism, 가중치를 축으로 쪼개는 방식)와 달리 양자화 블록을
  깨뜨리지 않음

## 교훈 반영 (설계 제약)

- 블록/그룹 양자화 MoE + TP는 EP 필수 — 카탈로그 추가 시 기본 점검 항목
- ELB 헬스체크 유예 60분, 이미지 태그는 실존 태그만, 스테일 컴파일 산출물 주의
- 유휴 가드와 기동 대기의 상호작용 — 스팟 확보 대기 중 ALB 무요청 상태가 지속되면 유휴
  자동정지 Lambda가 desired를 0으로 되돌려 확보 재시도가 멈춘 사례(2026-08-22 서울 실측).
  CLI의 기동 로직은 확보 완료까지 상시 핑 + desired 자동 복구를 내장할 것
